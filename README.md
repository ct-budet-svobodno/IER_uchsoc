## Роли пользователей

| Роль | Откуда берётся | Доступные команды |
|---|---|---|
| Обычный пользователь | любой | `/start`, меню, вопрос/предложение |
| Администратор | `ADMIN_IDS` в `.env`, либо является супер-админом | `/answer`, `/push`, `/secret` |
| Супер-администратор | `SUPER_ADMIN_IDS` в `.env` | всё, что у админа + `/chat`, `/admin`, `/super_admin`, `/messages` |

Обе переменные в `.env` — списки Telegram ID через запятую:

```
ADMIN_IDS=111111111,222222222
SUPER_ADMIN_IDS=111111111
```

Супер-админ автоматически считается админом: даже если его нет в `ADMIN_IDS`,
`/answer`, `/push` и `/secret` ему доступны.

Роли можно менять прямо из бота (`/admin`, `/super_admin`) — изменения применяются
мгновенно и сразу записываются в `.env`, поэтому переживают перезапуск.

## Команды администратора

### `/answer` — ответить на вопрос пользователя

1. Отправь `/answer` — бот попросит ввести ID вопроса (число).
2. Отправь ID — бот покажет текст вопроса и попросит написать ответ.
3. Отправь текст ответа — ответ доставлен пользователю и сохранён в БД.

Детали:
- если ID — не число, бот попросит ввести число заново;
- если вопроса с таким ID нет или на него уже отвечено — будет соответствующее сообщение;
- если ответ не удалось доставить (например, пользователь не запускал бота),
  он всё равно сохранится, а админ увидит предупреждение.

### `/push` — массовая рассылка

1. Отправь `/push` — бот попросит написать текст рассылки.
2. Отправь текст — бот отправит его всем пользователям в БД.

Детали:
- при упирании в лимиты Telegram бот автоматически ждёт (`TelegramRetryAfter`);
- в конце приходит отчёт: «Рассылка завершена: отправлено N, ошибок M»;
- сообщения отправляются без HTML-форматирования.

### `/secret` — заменить мемы «секретной кнопки»

1. Отправь `/secret` — бот покажет, сколько мемов сейчас на сервере, и попросит прислать фото.
2. Отправляй фото одно за другим (только `.jpg`) — каждое подтверждается «Сохранено (N)».
3. Когда закончишь, напиши `Стоп`.

Что произойдёт:
- все старые мемы удаляются, а новые сохраняются как `bot/data/photos/memes/meme_01.jpg …`;
- кэш `file_id` (`bot/data/meme_ids.json`) сбрасывается;
- при следующем запуске бот заново загрузит новые мемы в канал-хранилище.

Детали:
- если в режиме сбора отправить что-то кроме фото и «Стоп» — бот напомнит формат;
- если не отправлено ни одного фото — режим просто отменяется;
- во время сбора другие команды/тексты не обрабатываются (активен режим `secret`).

## Команды супер-администратора

Все команды супер-админа пошаговые: в конце каждого шага бот показывает «Шаг X из Y»
и что делать дальше. Если у пользователя нет прав — придёт «У вас нет прав супер-админа
на эту команду.»

### `/chat` — сменить чат для вопросов/предложений

1. «Шаг 1 из 2» — кнопкой выбрать, ID какого чата менять: «Чат активистов РГ (вопросы)»
   или «Чат руководителей (предложения)».
2. «Шаг 2 из 2» — ввести новый ID чата, например `<code>-1001234567890</code>`.

Что произойдёт:
- значение мгновенно применяется в памяти и записывается в `.env`
  (`QUESTIONS_CHAT_ID` или `SUGGESTIONS_CHAT_ID`);
- **рестарт не нужен** — бот перестанет направлять вопросы/предложения в старый чат сразу.

### `/admin` — выдача/снятие роли администратора

Для супер-админа:

1. «Шаг 1 из 2» — отправить Telegram ID пользователя (целое положительное число).
2. «Шаг 2 из 2» — нажать «✅ Выдать роль» или «❌ Забрать роль» (или «Отмена»).

Изменение применяется мгновенно и записывается в `ADMIN_IDS` в `.env`.

Для обычного пользователя эта команда показывает его ID и статус админа (см. выше).

### `/super_admin` — выдача/снятие роли супер-админа

1. «Шаг 1 из 2» — отправить Telegram ID пользователя.
2. «Шаг 2 из 2» — «✅ Выдать роль» или «❌ Забрать роль».

Изменение применяется мгновенно и записывается в `SUPER_ADMIN_IDS` в `.env`.

Защита: **нельзя снять роль супер-админа с самого себя** — бот покажет предупреждение
и не выполнит действие.

### `/messages` — редактирование текстов бота

Пошаговый редактор (4 шага):

1. «Шаг 1 из 4» — выбрать язык: «Русский» или «English».
2. «Шаг 2 из 4» — выбрать категорию, текст внутри которой меняется.
3. «Шаг 3 из 4» — выбор цели правки (зависит от категории):
   - для категории **«Вопросы и предложения»** — «Подтверждение вопроса» или
     «Подтверждение предложения» (сообщения, которые видит пользователь после
     отправки вопроса/предложения);
   - для категории **«Секретная кнопка»** (нет подкатегорий) — сразу переход к шагу 4:
     правится текст, выводимый под мемом;
   - для категории с подкатегориями — выбор конкретного вложенного ответа.
4. «Шаг 4 из 4» — бот показывает текущий текст и ждёт новый.

Что произойдёт:
- текст сохраняется в `bot/data/ru.json` или `bot/data/en.json` и сразу виден всем
  пользователям (файлы читаются на каждый запрос);
- после сохранения можно сразу править следующую категорию той же команды;
- доступны кнопки «⬅️ Назад» (к шагу 2) и «❌ Отмена» (полная отмена без изменений);
- если сохранение не удалось — придёт «❌ Не удалось сохранить текст. Проверь логи.»

## Переменные `.env`

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен бота от BotFather |
| `QUESTIONS_CHAT_ID` | чат, куда уходят вопросы активистов |
| `SUGGESTIONS_CHAT_ID` | чат, куда уходят предложения руководителей |
| `ADMIN_IDS` | Telegram ID администраторов (через запятую) |
| `SUPER_ADMIN_IDS` | Telegram ID супер-администраторов (через запятую) |
| `MEME_STORAGE_CHAT_ID` | чат-хранилище, куда бот разово загружает мемы и берёт `file_id` |
| `DATABASE_URL` | строка подключения к БД (по умолчанию sqlite) |

## Известные нюансы

- В `docker-compose.yml` объём `./data` монтируется в `/app/data`, тогда как код читает
  данные из `bot/data/`. Фактически volume не используется: `meme_ids.json`, мемы,
  загруженные через `/secret`, и SQLite-БД (`bot_data.db`) живут в слое контейнера и
  теряются при `down`/пересборке. При желании стоит пересмотреть путь монтирования.
- При смене мемов через `/secret` новые `file_id` появляются только после перезапуска
  бота (задача `ensure_meme_ids` работает на старте).
